# First workflow

The first test video proves the editor and the harness end to end ([roadmap step 1](roadmap.md#1-define-the-first-workflow)).
Its content stays neutral, because the channel's style and subject are still open.
Decisions were taken one at a time with the creator on 2026-11-12.

## Shape

**A 60 to 90 second narrated explainer in 16:9** (the creator, 2026-11-12).

- Inputs: a voiceover, 3 to 5 clips or stills, a title card, captions, and background music.
- Output: 1920x1080, 30 fps, H.264 video.
- It exercises cuts, trims, a transition, titles, captions, an audio mix, preview, undo, save and reopen, and export.
- That is the list roadmap step 2 asks Kdenlive to prove, so one video checks all of it.
- A vertical Short can reuse the same steps later.

Alternatives considered: a vertical Short under 60 seconds (fewer editing features), and a trimmed talking-head take (no titles, music, or stills).

## Inputs

**Every input is generated, including the narration** (the creator, 2026-11-12).

- Narration: text to speech from a fixed script saved with the brief, made locally with Kokoro-82M (the creator, 2026-11-12).
- Narration is also an app feature ([ADR 0008](adr/0008-narration-through-the-harness.md)). The test input builder uses the same engine, version, and voice as the app, all pinned.
- The first accepted narration file is kept by its hash and reused on reruns.
- Clips and stills: generated by a script, with exact, known lengths and sizes.
- Music: a generated bed with a known level.
- Captions: written from the narration script.
- Each input file's hash is recorded, so a rerun can prove it used the same inputs.
- The whole pack is rebuilt from the script and the brief, not stored in git.

Gap: the pipeline is not tested on a real recorded voice yet. Revisit this before the first real video.

Alternatives considered: a generated pack plus the creator's real recording, and only the creator's real recording.

## The edit

**A fixed edit list** (the creator, 2026-11-12). The script is about 70 seconds long and split into sentences.
Kokoro returns audio one segment at a time, so each sentence's start and end are known exactly.

1. Title card from 0 to 4 seconds, fading in.
2. Narration starts at 4 seconds on audio track 1.
3. Four picture segments, two clips and two stills, each cut at a sentence boundary.
4. Each clip starts partway into a longer generated source, not at its first frame.
5. One still has a slow keyframed zoom.
6. One 0.5 second crossfade between segments 2 and 3. Every other change is a hard cut.
7. A music bed on audio track 2 at a fixed lower level, fading out over the last 2 seconds.
8. One caption per sentence on Kdenlive's subtitle track, also exported as an SRT file.
9. A 2 second fade to black at the end.

Every editing feature is used once, at a time code can predict, so the export can be checked against exact values.

Alternatives considered: cuts only (leaves out trims, a transition, keyframes, and the music mix), and letting the harness choose the edit (not repeatable enough to check exactly).

## Text-to-speech facts

Read from the sources on 2026-11-12. Nothing has been installed or run.

- Kokoro-82M: weights and code are Apache-2.0. v1.0 (2025-01-27) has 8 languages and 54 voices. A Python library on PyTorch, with Windows and Apple Silicon notes. No word timestamps or determinism are documented.
- Piper: now developed as `piper1-gpl`, licensed GPL-3.0. Local, using espeak-ng. No release or platform list on its page.
- Gemini TTS: `gemini-3.8-flash-tts` and `gemini-3.8-flash-lite-tts` are current; older ones are previews. Output is 24 kHz mono 16-bit PCM WAV. No seed, determinism, or word timestamps are documented.
- None documents repeatable output, so a rerun reuses the accepted narration file by its hash ([project brief](project-brief.md#reproducible-production)). Whether a fresh generation matches is measured, not assumed.

Sources: [Kokoro-82M](https://huggingface.co/hexgrad/Kokoro-82M), [kokoro library](https://github.com/hexgrad/kokoro), [piper1-gpl](https://github.com/OHF-Voice/piper1-gpl), [Gemini speech generation](https://aistudio.google.com/docs/speech-generation).

## Acceptance checks

**Exact checks against the fixed edit list** (the creator, 2026-11-12). Code runs every check on the export.
The generated clips show a frame counter, so code can read which source frame appears in the export.

| Area | Passes when |
| --- | --- |
| Format | MP4 with fast start; H.264 High Profile, progressive, 4:2:0; 1920x1080 at 30 fps; about 8 Mbps; AAC-LC stereo, 48 kHz, 384 kbps. |
| Duration | The expected length within 1 frame. Audio and video streams end within 1 frame of each other. |
| Cuts and trims | At each cut, the exported frame shows exactly the expected source frame. |
| Crossfade | Frames in its 0.5 seconds blend both sources. It starts and ends within 1 frame of plan. |
| Zoom | The scale at its first and last frame is within 1% of the keyframes. |
| Narration | It starts at 4.000 seconds within 5 milliseconds, found by matching the export against the narration file. Kokoro's 24 kHz mono is converted to 48 kHz stereo. |
| Loudness | The mix is -14 LUFS integrated within 1 LU, with true peak at or below -1 dBTP. This is our chosen target. The music fades to silence by the end. |
| Captions | The SRT has one cue per sentence, text matching the script exactly, each start and end within 1 frame of the sentence times. |
| Ending | The last frame is black. |
| Save and reopen | The reopened project has the same timeline, and a second export decodes to the same frames. |
| Undo | Undoing every step returns to the empty project. Redoing returns to the same export. |
| Speed | Export time is recorded. No limit is set until it has been measured. |

Each check must fail when one deliberate mistake breaks it ([testing](testing.md)).

Alternatives considered: format checks only (a cut off by frames would pass), and a frame-by-frame reference video (breaks on any Kdenlive or encoder change).

## Creator review

**A checklist in the app** (the creator, 2026-11-12). Each item is marked pass or needs change, with a note.

- The narration sounds natural: pronunciation and pacing.
- The music sits under the voice.
- Cuts land at good moments.
- The crossfade and zoom look smooth.
- The title card is legible.
- Captions are readable: size, placement, and line length.
- The overall level is comfortable on phone speakers and on headphones.

The review is a versioned record tied to the export's hash.
A needs change note reaches that video's chat as a steer ([ADR 0006](adr/0006-long-running-chats-and-the-improvement-loop.md)).

Alternatives considered: free notes (no record of what was checked), and a 1 to 5 score per item (little to compare against).

## Two builds

**By hand first, then by the harness** (the creator, 2026-11-12).

1. Roadmap step 2: the edit list is built by hand in unchanged Kdenlive, with exact timecodes typed in. The export must pass every code check. This proves Kdenlive itself can do it.
2. Roadmap step 3: the Video chat builds it from one instruction and the brief. It narrates with `narrate`, places each item through the project gateway with undo, previews, exports, and runs the checks. The creator then reviews with the checklist.

Both exports must pass the same checks. A failure in the harness build then points to the harness, not Kdenlive.

Alternatives considered: harness only (a failure could be either), and the harness planning while the creator applies it (never proves the harness can edit).

## Where it ends

**At export in steps 2 and 3, then a private upload in step 4** (the creator, 2026-11-12).

- In roadmap step 4, the same export is the channel gateway's first test.
- It is uploaded privately with title, description, tags, chapters, the SRT captions, and a thumbnail.
- The test covers quota tracking, the resumable upload, and the approval prompt, which the creator refuses.
- It never goes public. It is generated test content, and it is marked as a test so grades never use it as a baseline.

Alternatives considered: export only (step 4 would test with a file not yet known to be good), and going public (a test video on the channel, skewing grades).

## YouTube upload settings

YouTube's recommended upload settings, read on 2026-11-12 ([YouTube Help](https://support.google.com/youtube/answer/1722171?hl=en)):

- MP4 with no edit lists and the moov atom at the front (fast start).
- H.264, progressive, High Profile, CABAC, 2 consecutive B-frames, closed GOP of half the frame rate, 4:2:0 chroma.
- Frame rate as recorded. For 1080p at 24 to 30 fps, 8 Mbps is recommended.
- Audio: AAC-LC (or Opus), stereo, 48 kHz, 384 kbps for stereo.
